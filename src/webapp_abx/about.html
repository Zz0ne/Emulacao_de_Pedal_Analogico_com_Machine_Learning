Finalidade

Este site é um protótipo client-side do teste ABX duplo-cego que integra o projeto final de licenciatura em Engenharia Informática. O projeto final desenvolve um plugin de áudio que emula, por Machine Learning, o pedal de distorção Darkglass Alpha Omicron. A validação percetual dessa emulação exige um teste ABX com participantes humanos. Aproveitei o enunciado deste e-fólio para prototipar toda a interface e lógica de teste em HTML, CSS e JavaScript puros.

Organização lógica

O site tem cinco páginas interligadas. A index.html funciona como menu de distribuição, com cards apontando para as secções. A project.html dá contexto sobre o projeto final e a metodologia black-box. A instructions.html explica o método ABX e o significado estatístico dos resultados. A test.html é o motor do teste, com três ecrãs (intro, trial, conclusão) controlados por JavaScript. A results.html apresenta a análise da última sessão. Esta página — about.html — é o relatório exigido pelo enunciado.

Separação de conteúdo e apresentação

Todo o estilo vive em três ficheiros CSS: base.css com variáveis, reset e tipografia; layout.css com a estrutura partilhada; e components.css com peças específicas (cards, botões, componentes do teste ABX). O HTML é semântico (<header>, <nav>, <main>, <section>, <footer>). As cores são todas definidas por variáveis CSS num único bloco :root, o que tornaria trivial implementar um tema alternativo sem tocar numa linha de HTML. A estrutura modular permite mudar completamente a apresentação alterando apenas CSS.

Funcionalidades dinâmicas

Foram implementadas quatro funcionalidades dinâmicas. Primeira: o motor do teste ABX, que gera doze trials com X aleatorizado, controla transições entre ecrãs e persiste o estado no localStorage, permitindo retomar uma sessão interrompida. Segunda: a síntese de áudio em tempo real via Web Audio API, que gera sinais de baixo distorcido com duas variantes (hardware e emulação) matematicamente próximas mas perceptivelmente distintas. Terceira: a barra de progresso, renderizada dinamicamente em JavaScript conforme o utilizador avança nos trials. Quarta: a análise estatística na página de resultados, com cálculo do p-value por distribuição binomial, d-prime por inversa da CDF normal, animação CSS da barra de performance e renderização de pills coloridas por trial.

Server-side info

e-fólio B · componente server-side · PHP + MariaDB

O e-fólio B acrescenta a este protótipo uma camada do lado do servidor que assegura persistência das sessões do teste em base de dados MariaDB, acedida via PHP. A lógica do teste mantém-se no cliente; o servidor recebe cada sessão concluída, valida-a e armazena-a, e expõe uma API REST que tanto o frontend do teste como o back-office consomem.

Esquema da base de dados

A base de dados efolioB_21182_2201022 contém três tabelas. trial_templates guarda os 12 slots de configuração da síntese; sessions guarda cada sessão ABX submetida; session_trials guarda os 12 trials de cada sessão, ligados à sessão e ao template correspondente.

trial_templates

campo tipo descrição
trial_index TINYINT (PK) identificador do slot, 0 a 11
label VARCHAR(80) etiqueta descritiva
waveform VARCHAR(20) sine, square, sawtooth ou triangle
frequency_hz DECIMAL(6,2) frequência fundamental em Hz
duration_ms INT duração do estímulo em ms
drive DECIMAL(4,2) ganho pré-distorção
updated_at DATETIME última modificação (automático)

sessions

campo tipo descrição
id INT (PK, auto) identificador da sessão, gerado pelo servidor
started_at DATETIME início do teste
finished_at DATETIME conclusão do teste
total_trials TINYINT número de trials (12)
hits TINYINT número de acertos
p_value DECIMAL(8,6) significância estatística
d_prime DECIMAL(6,3) índice de sensibilidade
client_ip VARCHAR(45) IP de origem (auditoria)
submitted_at DATETIME momento da submissão

session_trials

campo tipo descrição
session_id INT (PK, FK) sessão a que pertence
trial_index TINYINT (PK, FK) slot correspondente, 0 a 11
x_is CHAR(1) se X correspondeu a A ou B
answer CHAR(1) resposta do participante (A ou B)
correct BOOLEAN se a resposta foi correcta
answered_at DATETIME momento da resposta

Back-office

A página de back-office permite editar os 12 trial templates que parametrizam a síntese de áudio do teste. Cada slot é selecionável numa grelha; os parâmetros podem ser pré-escutados (variantes A e B) antes de serem submetidos. Os templates são um conjunto fixo por design — o teste tem sempre 12 trials — pelo que a operação é de edição, não de criação.

URL: backoffice.html

API REST

A API expõe dois recursos sob backend/api/, cada um servindo o método HTTP adequado à operação. As respostas são em JSON. O recurso sessions.php gere as sessões do teste; o recurso templates.php gere os parâmetros de síntese. Tanto o frontend do teste como o back-office são clientes desta API.

sessions.php

GET — listar todas as sessões

Devolve o resumo de todas as sessões submetidas, ordenadas da mais recente para a mais antiga. Sem parâmetros. 

curl "http://localhost/webapp_abx/backend/api/sessions.php"

GET — consultar uma sessão

Devolve uma sessão e os seus 12 trials. Parâmetro: id (inteiro, na query string). Responde 404 se a sessão não existir. 

curl "http://localhost/webapp_abx/backend/api/sessions.php?id=1"

POST — criar uma sessão

Recebe uma sessão concluída, gera o id no servidor e grava a sessão e os trials numa transação. Corpo: JSON com started_at, finished_at, total_trials, hits, p_value, d_prime e o array trials (cada um com trial_index, x_is, answer e answered_at). O servidor recalcula correct e valida que os hits declarados correspondem aos trials. Devolve o id atribuído. 

curl -X POST "http://localhost/webapp_abx/backend/api/sessions.php" \
  -H "Content-Type: application/json" \
  -d '{
    "started_at":"2026-05-31T14:30:00Z",
    "finished_at":"2026-05-31T14:38:00Z",
    "total_trials":12,"hits":1,"p_value":0.5,"d_prime":0.3,
    "trials":[
      {"trial_index":0,"x_is":"A","answer":"A","answered_at":"2026-05-31T14:31:00Z"},
      {"trial_index":1,"x_is":"B","answer":"A","answered_at":"2026-05-31T14:31:30Z"}
    ]
  }'

(Exemplo abreviado a 2 trials por brevidade; uma sessão real envia 12.)

templates.php

GET — listar os 12 templates

Devolve os 12 trial templates, ordenados por trial_index. Usado pelo teste (para sintetizar) e pelo back-office (para editar). Sem parâmetros. Com ?index=N, devolve apenas o template N. 

curl "http://localhost/webapp_abx/backend/api/templates.php"

PUT — atualizar um template

Substitui a configuração de um slot existente. Parâmetro: index (inteiro 0–11, na query string). Corpo: JSON com label, waveform, frequency_hz, duration_ms e drive. Responde 404 se o slot não existir. 

curl -X PUT "http://localhost/webapp_abx/backend/api/templates.php?index=0" \
  -H "Content-Type: application/json" \
  -d '{"label":"Mi (E1)","waveform":"sine","frequency_hz":41.20,"duration_ms":2000,"drive":6.0}'

Os dois recursos respondem 405 Method Not Allowed a métodos não suportados — sessions.php não permite PUT (as sessões são registos imutáveis, não se editam) e templates.php não permite POST (o conjunto de 12 templates é fixo, não se criam novos).
